更新日期：2026-09-23。网站代码目录：`D:\myweb`。这份文件放在项目的 `指南` 文件夹，之后可以直接从 README 的中文入口打开。

## 2. 已有文章怎么修改

1. 打开对应的 `content/posts/en/*.md` 文件，修改正文。
2. 修改开头的 `title` 或 `description` 可以同步更新标题、摘要。
3. 将 `updatedDate` 改为这次更新日期；保留原 `publishDate`。
4. 有中文译文时，同步修改相同类别 `zh` 目录下的文件。
5. 本地预览，然后按第 7 节发布。

现有作品的正文修改只需要改对应类别的 Markdown。独立 Writing 页面和房间纸张/电脑里的文章会一起更新。

## 3. 如何新增文章：以 my-new-article 为例

建议第一次直接复制 `no-pink-elephant` 的一整组文件作为模板。`my-new-article` 是网址名称（slug），使用英文小写和短横线。

### 第一步：创建内容文件

Articles 创建 `content/posts/en/my-new-article.md`；Essays 创建 `content/essays/en/my-new-article.md`；Poems 创建 `content/poems/en/my-new-article.md`。下面以 Articles 为例：

```markdown
---
title: My New Article
description: A short English introduction to this article.
publishDate: 2026-09-15
updatedDate: 2026-09-15
lang: en
translationKey: my-new-article
tags: [Web, Project]
draft: false
coverImage: /og.png
---

## Why I built this

Write the article here.

## What I learned

- First point.
- Second point.

[Source on GitHub](https://github.com/zacharyczy/your-project)
```

再在相同类别的 `zh` 目录创建 `my-new-article.md`，使用中文标题、摘要和正文，将 `lang` 改成 `zh`。两份文件的 `translationKey` 保持相同。

字段说明：内容目录决定文件存放位置，`tags` 决定网站里的 Articles / Essays / Poems 分类；`publishDate` 控制列表排序；`draft: true` 会从内容目录过滤。带 `Essay`、`Notes` 或 `随笔` 的文章进入随笔，带 `Poem`、`Poetry` 或 `诗歌` 的进入诗歌，其余进入文章。

当前 Markdown 渲染器比较轻量，适合普通段落、`##` 小标题、`-` 列表、代码块、行内代码、链接、粗体和删除线。Poems 按原稿换行显示。表格、图片嵌入、数学公式、多级标题等复杂语法没有完整实现；使用前先确认预览效果，或扩展 `components/markdown.tsx`。`coverImage` 是内容字段，目前普通文章页不会自动将它展示成正文大图。

### 第二步：注册文章

打开 `lib/content.ts`，在顶部增加：

```ts
import enMyNewArticle from '@/content/posts/en/my-new-article.md?raw';
import zhMyNewArticle from '@/content/posts/zh/my-new-article.md?raw';
```

找到 `const allPosts = [`，在数组里增加：

```ts
parsePost('my-new-article', enMyNewArticle),
parsePost('my-new-article', zhMyNewArticle),
```

**只把 Markdown 放进任一内容文件夹，目前不会自动出现。必须完成这个注册步骤。**

### 第三步：创建网址入口

复制：

- `app/blog/no-pink-elephant/page.tsx` → `app/blog/my-new-article/page.tsx`
- `app/blog/no-pink-elephant/zh/page.tsx` → `app/blog/my-new-article/zh/page.tsx`

在两个新文件中，将所有 `no-pink-elephant` 替换为 `my-new-article`。保留原来的 `en`、`zh` 分别对应英文和中文。

这样列表、正文页、房间阅读器、标签、站点地图和英文 RSS 就能使用新内容。

如果这次只有英文：内容目录可以只注册英文，但目前通用导航和文章页面模板默认存在配对译文；需要同时处理中文切换链接和 `alternates`，让它们指向实际存在的中文目录或隐藏。最容易维护的方式是按上述流程准备成对内容。草稿阶段可以先只在本地保存，不建立公开路由。

## 4. 随笔、诗歌和互动维护

当前实例：`content/essays/en/focus-takes-root-in-output.md` 与其中文配对，以及 `content/poems/en/apology.md` 与其中文配对。添加新作品时，在对应的 `essays` 或 `poems` 中创建中英文文件，给随笔加 `Essay` / `随笔` 标签、诗歌加 `Poem` / `诗歌` 标签，再按上节注册内容和创建页面路由。原稿里的一级标题由文章页面标题承担，正文可从标题之后开始。

每篇 Writing 的页面及房间阅读器都显示点赞与评论。同一语言版本的文章和评论由全体访客共享 Cloudflare D1 数据；每个浏览器访客标识对一篇作品或一条别人的评论只能点赞一次，在整个 Writing 中每天最多发两条评论。中文和英文译文作为两篇页面分别计数。读者没有账户，清理浏览器数据或更换设备会生成新的访客标识，因此这不是实名身份限制。

`/suggestions/` 和 `/suggestions/zh/` 是建议栏的直达页面，和导航抽屉共用原有建议数据。Writing 互动使用 `writing_comments` 与 `writing_likes` 两张表；发布代码时要先执行新数据库迁移，不能删除现有 Suggestions 表。

## 5. 如何新增 GitHub 项目

**新项目在自己的 GitHub 仓库上线，不会自动进入个人网站。网站的项目目录需要单独更新并推送。**

打开 `lib/projects.ts`，它有 `en` 和 `zh` 两个数组。在各自数组里增加一项：

```ts
{
  year: '2026',
  status: 'New',
  title: 'your-project',
  description: 'A concise description of what the project does.',
  stack: ['Python', 'CLI'],
  repository: 'https://github.com/zacharyczy/your-project',
  articleSlug: 'your-project',
},
```

中文数组使用同样的标题、仓库地址和 `articleSlug`，翻译 `status`、`description` 即可。项目顺序就是数组顺序，放在最前面就显示在最前面。

`articleSlug` 指向一篇站内项目文章。按第 3 节创建对应文章及页面，保证“阅读项目文章”按钮有内容可读。当前目录要求每个项目都有文章链接，不能只填写一个不存在的 slug。

项目页和房间电脑共用 `lib/projects.ts`，修改一次，两处都会更新。项目的源码、Release、README 仍在项目自己的仓库维护；网站只维护展示简介和对应文章。

## 6. 本地预览

在文件夹空白处右键打开终端，或在编辑器里打开 `D:\myweb` 后使用终端：

```powershell
cd D:\myweb
npm run dev
```

看到本地地址后，在浏览器打开 `http://localhost:3000/`。修改文件通常会自动刷新。

- Writing：`http://localhost:3000/blog/`
- 中文 Writing：`http://localhost:3000/blog/zh/`
- Projects：`http://localhost:3000/projects/`
- 新文章：`http://localhost:3000/blog/my-new-article/`

在新电脑或依赖变更后，先安装 Node.js 22.13 或更新版本，再运行 `npm ci` 安装锁定版本依赖。日常只改文字不需要每次安装。

如果端口被占用，使用终端显示的新端口；也可以停止已有的预览再启动。停止预览按 Ctrl+C。

目前开发工具偶尔在修改 Markdown 后出现热更新错误遮罩。先停止开发服务，再运行 `npm run dev` 并刷新页面；最终以类型检查、构建和实际页面结果判断。不要只关闭错误遮罩后就发布。

## 7. 如何正式发布

日常发布使用现有的 GitHub → Cloudflare 流程。在 `D:\myweb` 终端操作。

### 开始修改前同步

```powershell
git status
git branch --show-current
git pull --ff-only origin main
```

先确认自己的改动已经保存或提交，并且准备在 `main` 工作。已有未提交修改时不要强制覆盖；遇到冲突先处理，勿使用 `reset --hard` 清理工作。

### 本地检查

```powershell
npx tsc --noEmit --incremental false
npm run lint
npm run build
```

每一步都通过，再继续。浏览器还要打开新文章、项目链接和中文切换，确认房间内的对应入口正常。改人物运动时另外运行：

```powershell
node scripts/test-room-locomotion.mjs
node scripts/test-room-navigation.mjs
node scripts/test-room-layout.mjs
node scripts/test-room-ball.mjs
```

`test-*-browser.mjs` 是本机浏览器验收脚本，使用 `work/browser-tools` 中的 Playwright，需要 Chrome 和独立测试依赖；新电脑没有这个目录时先做手动验收。日常文章发布不要求安装整套房间测试工具。

### 提交和推送

先看清改动，再选择本次要发布的文件：

```powershell
git diff
git add content lib app README.md
# 如果同时改了房间，按需增加：
git add components
# 如果改了操作说明，按需增加：
git add 指南/网站维护指南.md
git diff --cached --stat
git commit -m "Add my new article and project"
git push origin main
```

这些 `git add` 路径是示例，只加入本次修改的内容。其他文件（如 `public`、配置或测试脚本）有意修改后也需要明确加入。

`commit` 是保存本地版本；**成功 `push origin main` 后才会触发网站发布**。只保存文件、只提交、或推送到项目自己的仓库，都不会更新 crazyczy.com。

Git 若提示 `dubious ownership`，先确认这就是自己的仓库，再对这个目录信任：`git config --global --add safe.directory D:/myweb`。如果 Git 提示缺少身份，填写你自己的 `user.name` 和 `user.email`，然后重新提交。

### 确认发布成功

打开 [网站仓库 Actions](https://github.com/zacharyczy/crazyczy.com/actions)，找到刚才提交触发的 `Deploy to Cloudflare`。

流程是安装依赖 → 构建 → 准备现有数据库 → 发布。等待整次运行变绿，再打开 [网站](https://crazyczy.com/) 验证。红色表示这次未成功，点开失败步骤查看原因；推送成功本身不代表已经上线。

Cloudflare 账号和令牌已由仓库 Secrets 管理，普通文章或项目更新无需重新创建令牌，也无需手动在 Cloudflare 上传文件。

## 8. 修改界面的建议顺序

先只改目标内容文件，再预览；需要改变布局时再改对应 `components` 和 `app/globals.css`。例如：

- 改欢迎语：在 `home-experience.tsx` 中搜索 `Hey, I am` 或 `Welcome to crazyczy.com`，分别修改 `WORDS.en` 与 `WORDS.zh`。
- 调照片位置：改 `room-artworks.ts` 中对应照片的 `position`。三维坐标依次为左右、高度、前后；先小幅修改，再看实际视角。
- 调手脚配色：改 `room-avatar.tsx` 中各方块的 `color`。
- 调跳跃：改 `room-locomotion.ts` 的 `JUMP_SPEED`、`GRAVITY`，再运行跳跃测试，检查最高点、落地和连续按键。
- 改文字阅读样式：查看 `globals.css`、`theme.css`、`room-study.css` 的 `.prose-tech`、`.article-wrap`、`.room-reader`。
- 改导航名称：查看 `lib/copy.ts`；增删栏目还要同步 `site-shell.tsx` 和终端导航。

房间与内页共用内容来源，通常不需要分别更新两个副本。

## 9. 哪些目录不用手工改

- `node_modules/`：安装的依赖。
- `dist/`、`.vinext/`：构建产物，下一次构建会重生成。
- `.wrangler/`：本地 Cloudflare 运行状态。
- `outputs/`：验收截图和报告；`work/`：临时检查工具。这两个目录默认不会上传。
- `.env*`：本地环境设置，已被忽略；不要把令牌写进文章、代码或 GitHub 提交。

Suggestions 的生产数据在数据库里，修改展示样式不会重置它。不要为了发布文章去手工删除或重建数据库。

## 10. 常见问题速查

| 现象 | 优先检查 |
| --- | --- |
| 新文章不在列表 | `lib/content.ts` 是否导入并加入 `allPosts`；`draft` 是否为 `false`；是否在正确分类和语言 |
| 列表有文章，点击 404 | 是否创建 `app/blog/slug/page.tsx`；slug 拼写是否一致 |
| 中文切换 404 | 是否有中文内容与 `app/blog/slug/zh/page.tsx`；`translationKey` 是否对应 |
| 新项目没出现 | 是否更新 `lib/projects.ts` 两个数组；是否已经推送网站仓库 |
| 项目文章按钮打不开 | `articleSlug` 是否对应已经注册并创建页面的文章 |
| 本地好了，线上没变 | 是否 push 到网站仓库的 main；Actions 是否绿色；刷新页面 |
| 地图本地没位置 | 正常：localhost 不伪造定位。线上使用网络大致位置，VPN 可能改变结果 |
| 手脚在读文章时消失 | 正常：取景、阅读和游戏期间会隐藏人物，避免遮挡内容 |

本轮可参考的完整实例：`content/posts/en/no-pink-elephant.md`、对应中文文件、`app/blog/no-pink-elephant/` 和 `lib/projects.ts` 的第一项。
